3. LAUNCH COUNT, ALLOCATOR PEAK, REPEAT SPREAD, GUARDS
==============================================================================
  THE ALLOCATOR-PEAK CAVEAT, and it is not a small one. MemProbe sees
  exactly one thing: calls to Allocator.alloc. tinygrad's CUDA backend
  CACHES device buffers, so only the FIRST graph built at a given shape
  goes through cudaMalloc. Every later graph at the same shape is served
  from buffers the process already holds, so n_allocs reads 0 and the
  probe's live-bytes high-water mark reads 0 -- an artefact of the
  measurement ORDER, not a statement that the rung allocates nothing.
  Five rungs in one process therefore yield ONE clean peak per shape, on
  whichever rung happened to be measured first.
